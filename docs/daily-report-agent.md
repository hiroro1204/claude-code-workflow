# 事例：工数記録（日報）を作る業務自動化エージェント

アルバイト先で毎日つける工数記録を、Claude Code のスキルで作れるようにした事例です。
スキル本体には社内の人名・案件名・シートの情報が含まれるため公開していません。ここでは設計と、作りながら判断したことを説明します。

## 解決したかったこと

工数記録は、1日の作業を「日付・時刻・依頼元・案件・作業内容」などの列に分けて、共有のスプレッドシートに書く仕事です。
材料は3か所に分かれていました。

- **Toggl Track**：実際に作業した時間
- **Notion**：タスクごとに承認された時間（承認枠）
- **Discord**：報告・連絡・相談の投稿（Toggl には記録されない）

毎日これを見比べて手で転記するのに時間がかかり、記入漏れも起きていました。

## 流れ

```
Toggl API で実作業を取得
  ↓
Notion の承認枠と突き合わせ（超過は5分以内なら自動調整、それ以上は聞く）
  ↓
Discord を検索して、報告・相談の投稿を拾う
  ↓
足りない情報・あいまいな点を「まとめて1回だけ」質問
  ↓
確認用の表を出す（行番号つき・その日の合計時間つき）
  ↓
表記の辞書を更新 → Notion のタスク状態を更新
  ↓
GAS（Apps Script のウェブアプリ）で自分用のコピーシートに書き込み → 読み返して確認
```

## 設計で大事にしたこと

### 1. AI に任せる範囲と、人が確認する範囲を分ける

- AI が書き込むのは**自分用のコピーシートだけ**。他のメンバーも使う本番の共有シートには書かない
- 本番へは、人がコピーから「値のみ貼り付け」で移す（普通に貼るとプルダウンが壊れるため）
- 推測で埋めない。わからない項目は聞く
- 実際の作業時間を、承認枠に合わせて勝手に削らない（5分を超える差は必ず聞く）

### 2. 質問の往復を減らす

1つずつ聞くと会話が長くなるため、確認したいことは**1つのメッセージにまとめて**聞く流れにしました。

### 3. 音声入力の誤認識に強くする

音声入力で話すため、案件名や人名がよく崩れます（例：「様子とSEO」→ Yoast SEO）。次の順で照らし合わせます。

1. 完全一致
2. 表記ゆれの辞書
3. 部分一致
4. カタカナ・英字・全角半角をそろえて比較
5. 読みが同じ漢字の変換ミスを疑う
6. 同じ日の前後の作業から推定

1つに決まれば直して報告し、候補が複数あれば聞きます。新しい誤認識がわかったら辞書に足すので、**使うほど聞き返しが減ります**。

## うまくいったこと

- 3か所を見比べて転記する作業がほぼなくなり、毎日の記録にかかる時間が大きく減った
- 約2か月分の記録を、このスキルでまとめて作成できた
- 承認枠の超過や、時間の重複に気づけるようになった

## 難しかったこと

| 起きたこと | 対応 |
|---|---|
| ブラウザ自動操作（Playwright）でスプレッドシートに書こうとしたが、セルが画面の絵として描かれていて動作が不安定 | GAS のウェブアプリを作り、API 経由で書き込む方式に変更 |
| 共有シートを AI が誤って壊すおそれがある | 書き込み先を自分用のコピーに限定。本番へは人が移す |
| AI の操作ミスで、チャットに意図しない投稿をしかけた | 「Discord は読むだけで投稿しない」をルールとして明文化 |
| 音声入力で人名・案件名がずれる | 辞書と照合の手順を作り、合わないものは勝手に直さず確認 |
| Bash から Windows のユーザー環境変数が見えず、API トークンが読めない | PowerShell で読み込んでから呼び出す手順に統一 |

一番学んだのは、**AI に何を任せ、どこで人が確認するかの線引きを先に設計すること**です。

## 使った技術

Claude Code（スキル）／ Toggl Track API ／ Notion MCP ／ ブラウザ操作（Claude in Chrome）・画面操作（Discord の検索）／ Google Apps Script ／ Python ／ PowerShell
